## 0. What If the Model Could Look Back?

The Seq2Seq bottleneck was a compression problem. The encoder was forced to squeeze an arbitrarily long input into a single fixed-size vector, and the decoder had to reconstruct meaning from that one vector alone. The information it needed might be anywhere in the input — buried in paragraph 3, referenced again in paragraph 47 — but the decoder had no way to go back and look.

The fix, in retrospect, is almost obvious: give the decoder a direct line to every encoder hidden state, not just the last one. At each generation step, let the decoder look back across the full input and decide, dynamically, which parts deserve the most attention right now.

This idea — giving the decoder dynamic, weighted access to the full encoder output — was introduced in Bahdanau et al. (2015). It lifted translation quality dramatically, especially on long sentences. But more importantly, it contained an insight that would later be generalized far beyond Seq2Seq: the attention weight itself is a learned function of the current context, computed on the fly.

## 1. The Attention Mechanism

The attention mechanism formalizes this idea using three components: a **Query**, a set of **Keys**, and a set of **Values**.

The intuition maps cleanly onto information retrieval. The Query is what you're currently looking for. Each Key is a label describing what a particular piece of information contains. The Value is the actual content of that information. Attention computes how well the Query matches each Key, uses those match scores to weight the Values, and returns a weighted sum.

In the original Seq2Seq with attention, the Query comes from the decoder's current hidden state and the Keys and Values both come from the encoder's hidden states. In matrix form, with $n$ input tokens and $m$ output steps, the computation is

$$\text{Attention}(Q, K, V) = \text{softmax}\!\left(\frac{QK^T}{\sqrt{d_k}}\right)\!V$$

where $Q \in \mathbb{R}^{m \times d_k}$, $K \in \mathbb{R}^{n \times d_k}$, $V \in \mathbb{R}^{n \times d_v}$.

The $QK^T$ term computes a dot product between every Query vector and every Key vector simultaneously — producing an $m \times n$ matrix of raw similarity scores. Softmax normalizes each row into a probability distribution over the $n$ input positions. Multiplying by $V$ then returns a weighted sum of value vectors, one per output step.

One thing that confused me was why we divide by $\sqrt{d_k}$. When $d_k$ is large, dot products between randomly initialized vectors tend to be large in magnitude, which pushes softmax into regions where the gradient is nearly zero — all the weight concentrates on one position and learning stalls. Dividing by $\sqrt{d_k}$ keeps the inputs to softmax in a variance-controlled range regardless of embedding dimension.

## 2. Self-Attention

The attention mechanism described above connects two different sequences — decoder queries attending to encoder keys and values. But the 2017 Transformer paper applied the same computation within a single sequence: every position attending to every other position in the same sequence. This is **self-attention**.

In self-attention, the Query, Key, and Value matrices are all derived from the same input $X$ through learned linear projections

$$Q = XW^Q, \quad K = XW^K, \quad V = XW^V$$

where $W^Q, W^K, W^V \in \mathbb{R}^{d_{model} \times d_k}$ are learned weight matrices. The same formula applies

$$\text{Self-Attention}(X) = \text{softmax}\!\left(\frac{XW^Q (XW^K)^T}{\sqrt{d_k}}\right)\!XW^V$$

The question this answers is no longer "which encoder states are relevant to my current decoder step?" but rather "which other positions in this sequence are relevant to understanding each position?" This makes self-attention a general-purpose tool for capturing within-sequence relationships.

For a risk model reading "The Fed tightened policy significantly, which impacted credit markets, and it also pressured equity valuations" — correctly resolving "it" to "policy tightening" rather than "credit markets" requires understanding the sentence's full structure simultaneously. Self-attention handles this because every position can attend to every other position directly, with no information forced through a sequential bottleneck.

One thing that confused me was the distinction between self-attention and the cross-attention used in Seq2Seq. In self-attention, $Q$, $K$, and $V$ all come from the same sequence — the model asks "how do the positions within this sequence relate to each other?" In cross-attention, $Q$ comes from one sequence (the decoder) and $K$, $V$ come from another (the encoder). The computation is identical; only the source of the inputs differs.

## 3. Multi-Head Attention

Running self-attention once gives the model one set of relationships across the sequence. But a single attention computation forces all the information into one representation — one learned similarity function, one set of weight matrices. A sentence like "Revenue beat estimates, but guidance disappointed" contains multiple overlapping relationship structures: syntactic (subject-verb), semantic (positive vs. negative sentiment), and numeric (earnings figures vs. guidance figures). Asking a single attention head to capture all of these simultaneously is too much.

The Transformer's answer is to run several attention computations in parallel, each with its own projection matrices

$$\text{head}_i = \text{Attention}(QW_i^Q,\, KW_i^K,\, VW_i^V)$$

and then concatenate the results and project back to the model dimension

$$\text{MultiHead}(Q, K, V) = \text{Concat}(\text{head}_1, \ldots, \text{head}_h)\, W^O$$

Each head operates in a lower-dimensional subspace of size $d_k = d_{model}/h$, so the total computation remains comparable to a single full-dimensional attention. With $h = 8$ heads and $d_{model} = 512$, each head works in a 64-dimensional space.

One thing that confused me was whether multi-head attention is just the same computation repeated $h$ times. It isn't. Each head has its own projection matrices $W_i^Q$, $W_i^K$, $W_i^V$, so each head learns to ask a different kind of question about the input. Empirically, different heads in trained Transformers specialize — some track syntactic dependencies, others track semantic relationships, others handle coreference. This specialization emerges from training, not from any explicit supervision.

## 4. Positional Encoding

Self-attention, as described so far, has a fundamental symmetry problem. The attention score between position $i$ and position $j$ depends only on the content of the vectors at those positions — not on whether $i$ comes before or after $j$ in the sequence. Feed the model "Revenue beat expectations" or "Expectations beat revenue" and it computes identical attention patterns, because the operation is invariant to permutation.

This is the price of parallel processing. The LSTM paid nothing for positional information — it was implicit in the order tokens were fed in. The Transformer processes all tokens simultaneously and gets parallelism for free, but loses position for free too. Position has to be added back in explicitly.

The Transformer paper's solution was to construct a fixed function that maps each position to a unique vector and add it to the token embedding before the first attention layer

$$PE_{(pos,\, 2i)} = \sin\!\left(\frac{pos}{10000^{2i/d_{model}}}\right), \qquad PE_{(pos,\, 2i+1)} = \cos\!\left(\frac{pos}{10000^{2i/d_{model}}}\right)$$

Each dimension oscillates at a different frequency — low-index dimensions complete many cycles across the sequence length, high-index dimensions barely move. Every position $pos$ maps to a unique combination of values across all $d_{model}$ dimensions, so no two positions are ever confused. More importantly, the relative offset between positions is also encoded: the vector at position $pos + k$ can be expressed as a linear function of the vector at position $pos$, which means the model can learn to reason about distance without any explicit engineering.

One thing that confused me was why sin and cos specifically, rather than just learning position embeddings the way BERT does. Both approaches work in practice. The sin/cos formulation has one theoretical advantage: it may generalize to sequence lengths longer than those seen during training, because the encoding function is defined for any $pos$. Learned embeddings are bounded by the maximum sequence length seen during training. For most practical applications the difference is small, but it was an early design choice that stuck.

## 5. The Full Transformer

With self-attention, multi-head attention, and positional encoding in place, the Transformer assembles these into two stacked modules: an encoder and a decoder. Both share the same internal structure, with one key difference.

Each **encoder layer** contains two sub-layers: multi-head self-attention followed by a position-wise feed-forward network

$$\text{FFN}(x) = \max(0,\; xW_1 + b_1)\, W_2 + b_2$$

Each sub-layer is wrapped with a residual connection and layer normalization

$$\text{output} = \text{LayerNorm}(x + \text{Sublayer}(x))$$

The residual connection preserves the original signal through the transformation — gradients flow back through the addition operation unchanged, which is the same insight that makes ResNets trainable at depth. Layer normalization stabilizes the scale of activations across the sequence, preventing the kind of gradient instability that troubled deep RNNs.

The **decoder** has one additional component: a cross-attention layer between the masked self-attention and the feed-forward network. In cross-attention, the Queries come from the decoder's previous layer and the Keys and Values come from the encoder's output. This is the mechanism through which the decoder reads the input — at every generation step, for every decoder position, the model can directly access any part of the encoded input with attention weights computed on the fly.

The decoder's self-attention layer is **masked** — when generating position $t$, the model can only attend to positions $1, \ldots, t-1$, not to future positions it hasn't generated yet. Without masking, the model could trivially predict position $t$ by looking at position $t+1$, which would make training easy but inference impossible.

The original Transformer used $N = 6$ encoder layers and $N = 6$ decoder layers, $d_{model} = 512$, $h = 8$ heads, and $d_{ff} = 2048$ for the feed-forward layer. This remained the reference architecture for nearly everything that followed.

What changed with the Transformer wasn't just performance — it was throughput. Because self-attention is a pure matrix operation, all positions in a sequence can be processed simultaneously. Training on long sequences, which had been painfully slow with LSTMs due to sequential dependency, became a parallelizable matrix multiply. This is why scaling to billions of parameters became possible: GPUs could finally be utilized efficiently for sequence modeling. The Transformer didn't just improve translation quality. It opened the door to every large language model that followed.
